# SEO Audit — 2026-08-24

## Context

Brand search for "korovatron" stopped returning the root index as a blue link result after the gallery feature was added. The gallery introduced `loadGalleryData().then(loadContent)`, which gated all card rendering behind an async JSON fetch. When Googlebot's rendering budget was exhausted or the Fastly CDN served a stale cached version of the JSON, the root index appeared as a near-empty page. Repeated bad crawls degraded Google's quality signals for the page, causing it to drop from brand search results.

Bing was unaffected because it extracts brand signals from static `<head>` content (title, meta, LD+JSON) without requiring JavaScript execution.

---

## Fixes Applied Today

### Root index (`index.html`)
- `loadContent()` now runs **synchronously on page load** — cards render immediately without any fetch dependency
- `hasGallery: true` hardcoded on 13 apps — gallery buttons render without depending on the JSON
- All gallery data fetch code removed entirely — the page is now fully static with zero async dependencies

### Gallery page (`gallery/index.html`)
- Page is now **pre-rendered at build time** from `gallery-data.json` + `gallery/index-template.html`
- All 101 images hardcoded as static HTML — no fetch, no CDN caching risk
- `filterGallery()` handles `?app=` filtering via synchronous DOM manipulation only
- Removed accidental `noindex` meta tag that was blocking all gallery pages from being indexed

### Build workflow
- Run `node build-gallery.js` after editing `images/galleries/gallery-data.json`
- See `GALLERY-BUILD.md` for full instructions

## Site-wide Audit Findings

### Critical — Directly caused brand search failure

| Issue | Detail |
|-------|--------|
| JS-gated content rendering | `loadContent()` was async — empty page on crawl failures |
| Stale CDN cache on gallery JSON | Fastly ignored `Cache-Control: no-cache` headers; fixed with `?t=${Date.now()}` cache-bust |
| Gallery `noindex` baked into output | Template noindex tag compiled into served HTML, blocking all gallery pages |

### Medium — Structural brand signal weakness

**No app page includes "Korovatron" in its `<title>` tag.**

Current pattern: `Free Online Graphing Calculator & Graph Plotter | Graphiti`  
Recommended pattern: `Graphiti | Online Graphing Calculator | Korovatron`

This was working before (brand search was fine), so restoring it is a nice-to-have improvement rather than the immediate fix. But it is a structural weakness — if the root index has problems again, there is no fallback brand signal anywhere in the 17 sub-pages.

**No app LD+JSON links back to the root Organisation entity.**  
None of the app pages reference:
```json
"publisher": { "@id": "https://www.korovatron.co.uk/#organization" }
```
or
```json
"isPartOf": { "@id": "https://www.korovatron.co.uk/#website" }
```
The Knowledge Graph is fragmented — the Organisation entity defined in the root index is completely disconnected from the app sub-sites.

**`og:site_name` missing on 8 apps:** `vectorama`, `mandelscope`, `boolinator`, `chewring`, `pacman`, `tetris`, `spaceinvaders`, `qorby`

## Structured Data — Root Index

The root index `WebPage` entity has:
```json
"about": { "@id": "https://www.korovatron.co.uk/#app-list" }
```
This tells Google the page is "about a list of apps" rather than "about the Korovatron brand". Consider changing to:
```json
"about": { "@id": "https://www.korovatron.co.uk/#organization" }
```
This signals to Google that the homepage IS the brand homepage, which is more appropriate for brand query ranking.
